# 05 — Atribuciones fuera de GitHub (2026-10-02)

**TL;DR.** El owner detecta atribuciones en GitHub pese a D37. Estaban en los mensajes de los dos últimos commits de `main` (#13 y la release `v0.6.0`: trailers `Co-authored-by` y `Claude-Session`) y en las descripciones de los PR #13 y #14 (pie «Generated by Claude Code» y enlace de sesión). Venían de la sesión web de la bitácora 04, a la que no llega el `includeCoAuthoredBy: false` local. El owner elige reescribir `main` y el tag y además blindar (D64).

## Qué se hizo
- PR #13 y #14: descripciones editadas sin el enlace ni el pie.
- `main`: los mensajes de `423a0b8` y `877d49f` se reescribieron (`git filter-branch --msg-filter` sobre `039d8b4..main`). Árbol idéntico: `git diff` vacío entre el `main` antiguo y el nuevo (`0bc943a`). Ningún otro commit ni tag tenía atribuciones.
- Protección de `main`: `allow_force_pushes` activado y `enforce_admins` desactivado solo durante el `push --force-with-lease`, y restaurados igual que antes (PR obligatorio, check `ci` estricto, sin borrado, también para el administrador). Un primer intento con `enforce_admins` activado lo rechazó GitHub: con la regla de PR obligatorio, permitir el force-push no basta.
- Tag `v0.6.0`: recreado (anotado, mismo mensaje) sobre `0bc943a` y empujado; `release.yml` reconstruyó la imagen con el mismo contenido y movió `latest`.
- Barreras: `scripts/attribution-check.sh` (`make attribution-check`, dentro de `make ci`) revisa los mensajes de commit de la rama y `PR_BODY`; `ci.yml` pasa la descripción del PR, hace checkout completo y también corre al editar un PR. El hook `PreToolUse` de Bash deniega `git commit|tag` y `gh pr|issue|release` con atribución en el comando; probado con cuatro casos (dos se deniegan, dos pasan). Comprobado contra el historial antiguo: el script falla sobre los dos commits originales.

## Hallazgos
- El hook es deliberadamente amplio: también salta con un heredoc que solo *menciona* `git commit` y un trailer. Coste aceptable: el mensaje dice qué ha pasado; para escribir docs sobre el tema se usa Edit.
- Quien tenga un clon de `main` anterior a hoy en otra máquina debe hacer `git fetch && git reset --hard origin/main` (el hook `SessionStart` lo avisará como divergencia; `git cherry` no mostrará líneas `+`, porque los parches son los mismos).
